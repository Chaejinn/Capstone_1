# 웹 카메라의 호모그래피·ArUco 설정

`browser_vision.py`는 기존에 운영하던 CPU 추적 어댑터를 기준으로 한 유지보수 사본입니다.
RF-DETR/Moondream GPU 모델은 바꾸지 않습니다. 공유 설정 스키마는
`backend/platform/camera_configuration.py`, 실제 OpenCV 처리는 `camera_runtime.py`에 있습니다.

Vercel의 `camera_configurations` 테이블은 사이트·카메라별 설정과 버전을 보관합니다.
관리자는 호모그래피와 ArUco를 별도 PUT API로 저장합니다. 새 스트림을 만들 때
Vercel이 저장된 설정을 인증된 CPU 서비스에 전달하고, 서비스가 같은 버전을 적용했다고
응답했는지 확인합니다. 활성 카메라는 설정 저장 후 미디어 연결은 유지하고 추적 세션만 재생성합니다.
이때 대상 ID와 15프레임 누적도 새 세션에서 다시 시작합니다.

호모그래피 점은 원본 전체 영상 기준 0~100 상대좌표입니다. 분석용 이미지가 축소되면
같은 비율로 보정점을 변환합니다. 영상 종횡비가 1% 넘게 다르면 실좌표를 거부합니다.
호모그래피와 ROI는 별도입니다. 마커 중심과 선수 방향은 마커 네 모서리를 수면 평면에
투영해 계산하며, 3D 자세를 계산하는 기능이 아닙니다.

ArUco는 호모그래피 없이도 마커 ID·영상 좌표·픽셀 헤딩을 검출합니다.
실좌표에는 호모그래피가, 보트 선수 헤딩에는 실측 오프셋 확인이 필요합니다.
수신된 프레임의 시각을 새 시각으로 덮어쓰지 않으며, 기존 2초 프레임 접수·0.2초 포즈 검증·
0.25초 포즈 만료 규칙은 유지합니다. 분석 화면의 마커·실좌표는 해당 과거 분석 프레임의
정보이며 현재 제어 가능한 보트 위치를 뜻하지 않습니다. 실제 출동 명령을 생성하지 않습니다.

## 배포

현재 작업 환경에 기존 `local-model/modal-moondream2-deploy/` 빌드 컨텍스트가 있습니다.
여기에는 11월 6일에 배포한 `src/flow`, 추론 API 클라이언트와 strict gate 등 CPU 어댑터의
의존 소스가 있습니다. 이 폴더와 모델 가중치는 Git/Vercel 패키징에서 제외됩니다.
새로운 PC에서는 해당 기존 소스 리비전을 먼저 준비해야 하며, 최신 AI 저장소의 폴더명만
바꿔서 동일한 컨텍스트라고 간주하면 안 됩니다.

```sh
python3 scripts/prepare-tracking.py
# 기존 Vercel VISION_SERVICE_API_KEY 값을 VISION_INGEST_API_KEY 환경변수로 전달한 환경에서:
cd local-model/modal-moondream2-deploy
../.venv-modal/bin/python -m modal deploy tracking_app.py
```

이 단계는 CPU 추적 서비스 `drown-guardian-web-tracking`만 갱신합니다.
서비스 키는 기존 값을 재사용하고, 파일·명령줄·로그에 키를 기록하지 않습니다.

Vercel 웹은 별도로 새 설정 UI/API를 배포해야 합니다. 카메라 PC 도구 `edge-vision/`은
별도 설정 파일을 쓰므로 이 웹 설정을 자동으로 덮어쓰지 않습니다.

## 검증 범위

합성 마커 영상으로 독립 마커 검출, 축소 영상의 실좌표, 실측 헤딩 요구, 설정 버전 전달,
비활성화·유효하지 않은 점·사이트 접근·관리자 저장 권한을 검증합니다.
실제 현장 카메라에서는 수조 크기·기준점·마커 크기·오프셋을 직접 측정해야 합니다.
