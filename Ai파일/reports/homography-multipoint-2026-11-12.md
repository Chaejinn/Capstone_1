# 웹 호모그래피 기준점 개수 제한 제거

- 웹의 `image_points`에서 4개 최대 개수 제한을 제거했습니다.
- 첫 4점은 기존과 같이 수조 경계를 정의하고, 추가 점은 계속 선택·개별 삭제할 수 있습니다.
- 추가 점별 실제 X·Y 좌표 입력 표와 점별/RMS/최대 재투영 오차 표시를 추가했습니다.
- 모든 영상점/실제점 대응을 정규화한 DLT 계산에 함께 사용합니다.
- 실제 CPU 처리도 같은 행렬을 사용하며, 축소 영상에는 같은 비율의 픽셀 변환을 적용합니다.
- ROI는 경계 4점으로 유지하여 내부 점을 추가한 순서 때문에 다각형이 뒤틀리지 않습니다.
- 영상점/실제점 개수 불일치, 중복, 수조 밖 좌표와 최대 재투영 오차 5cm 초과를 거부합니다.
- 기존 4점 저장값에는 별도 데이터 마이그레이션이 필요 없습니다.
- 점 개수 상한을 별도로 두지 않지만 브라우저·서버 메모리와 플랫폼 요청 크기 한계는 적용됩니다.

검증:

- 설정 API 테스트 7개 통과. 965점 저장·재조회·점별 오차 반환을 포함합니다.
- 추가 대응점의 값이 실제 계산 결과를 바꾸는지 확인했습니다.
- CPU 통합 테스트 4개 통과. 53점과 축소 영상, 기존 4점, 독립 ArUco를 포함합니다.
- JS 설정 테스트에서 연속 점 추가·좌표 누락 차단·실제 좌표 저장·개별 삭제를 확인했습니다.
- 기존 카메라·ROI·edge JS 테스트와 통합 서버 테스트 7개가 통과했습니다.
- Chrome에서 7점 선택·실제 좌표 입력·재저장 및 ArUco 설정 보존을 확인했습니다
  (생성한 영상과 모의 저장 API 사용).
- Modal CPU 추적 서비스 배포 후 실제 API에 합성 영상과 965점 설정을 전달해
  마커 좌표·헤딩 변환, 점별 보고서, 설정 버전 응답과 임시 스트림 삭제를 확인했습니다.
  실제 사이트 설정이나 물리적 보트 제어는 변경하지 않았습니다.

실측 기준점의 정확도와 현장 카메라 환경은 별도 확인이 필요합니다.
