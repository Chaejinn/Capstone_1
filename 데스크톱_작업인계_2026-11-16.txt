Drown Guardian — Windows 데스크톱 작업 인계
작성일: 2026-11-16 (한국 시간)

1. 현재 상황과 작업 범위
- Mac의 HC-06 연결은 완료되지 않았습니다. Windows 데스크톱에서 이어서 진행합니다.
- 웹·AI 운영 배포는 되어 있습니다. 데스크톱에서 우선 운영 웹을 사용하면 됩니다.
- 실제 보드 통신, PID 조향 튜닝, 출동·복귀·완료까지 검증된 상태는 아닙니다.
- 비밀번호·API 키·로그인 토큰은 이 파일에 포함하지 않았습니다.

2. 운영 주소와 저장소
관제 웹: https://drown-guardian.vercel.app
로그인: https://drown-guardian.vercel.app/index.html
신호 테스트: https://drown-guardian.vercel.app/signal-test.html
웹 코드: https://github.com/DrownGuardian/Web-Platform
동기화 저장소: https://github.com/Chaejinn/Capstone_1
AI 담당 원본 저장소: https://github.com/DrownGuardian/Detective-model

웹 코드 저장소 하나만 받으면 됩니다. Web-Platform과 Capstone_1을 동시에 복제할 필요는 없습니다.

PowerShell:
git clone https://github.com/DrownGuardian/Web-Platform.git
cd Web-Platform

이미 받았다면 해당 폴더에서:
git status
git pull --ff-only

로컬 변경이 있으면 덮어쓰거나 강제 초기화하지 말고 먼저 보존하세요.

3. 우선 준비할 것
- Git, Python 3.12, Chrome 또는 Edge
- 카메라와 고정 장치, 수조, 자/줄자, 출력한 ArUco 마커
- 정상 동작이 확인된 보드·Bluetooth 모듈, 해당 펌웨어와 배선 정보
- HC-06에 연결된 다른 PC의 브릿지는 종료하고 Bluetooth 연결도 해제
- 운영 웹의 본인 계정 로그인 정보 (별도 전달)

4. Windows 브릿지 실행 환경
프로젝트 루트 PowerShell에서 아래 명령을 한 줄씩 실행합니다.
가상환경 활성화는 필요 없습니다.

py -3.12 -m venv .venv-bridge
.\.venv-bridge\Scripts\python.exe -m pip install requests pyserial
.\.venv-bridge\Scripts\python.exe signal_bridge.py --list-ports

HC-06을 Windows Bluetooth 설정에서 페어링합니다.
하드웨어 담당자가 안내한 PIN은 1234이며, 실제 모듈 설정이 바뀌었다면 담당자에게 확인합니다.
추가 Bluetooth 설정의 COM 포트에서 '송신/나가는 포트'를 확인합니다.
COM4는 예시이며 실제 포트 번호를 사용해야 합니다.
--list-ports는 포트 목록 확인 기능이며, 보드 연결 성공을 보증하지는 않습니다.

5. 새 로그인 토큰 준비
운영 웹에 데스크톱에서 새로 로그인합니다. 이전에 채팅으로 전달받은 토큰은 재사용하지 않습니다.
로그인한 같은 탭에서 F12 → Console을 열고 다음을 실행하면 토큰만 클립보드로 복사됩니다.

copy(JSON.parse(sessionStorage.getItem('dg_api_session')).token)

dg_api_session이 없거나 로그인이 만료됐다면 다시 로그인합니다.
Console 자체가 코드를 붙여넣지 못하게 막는다면 경고를 무작정 해제하지 말고,
DevTools Application → Session Storage → 해당 웹 주소 → dg_api_session의 token 값을 확인합니다.
토큰을 채팅·Git·소스 파일에 붙이지 마세요.

PowerShell에서:
$env:DG_BRIDGE_TOKEN = Read-Host "방금 복사한 로그인 토큰 붙여넣기"
$env:DG_BRIDGE_PORT = "COM4"

COM4를 실제 송신 포트로 바꿉니다. 이 환경변수는 현재 터미널에서만 적용됩니다.

6. 실제 보드 연결 전 확인 — 중요
signal-test.html은 로그인/접속 시 자동 임의 명령 생성을 시작할 수 있습니다.
이 명령을 signal_bridge.py가 읽으면 실제 보드에 전달할 수 있으므로,
브릿지를 실제로 실행하기 전에 '자동 테스트 중지'를 누르세요.
페이지를 닫는 것만으로 서버의 자동 생성이 종료되는 것은 아닙니다.
다른 사용자도 같은 서버의 테스트 명령을 만들 수 있으므로 테스트 시간을 조율합니다.

같은 로그인 탭의 Console에서 아래 조회로 중지 상태를 확인할 수도 있습니다.
await dgApi('/test-control/auto')

중지가 필요하면:
await dgApi('/test-control/auto/stop', {method:'POST'})

우선 하드웨어를 열지 않는 조회 확인부터 실행합니다.
.\.venv-bridge\Scripts\python.exe signal_bridge.py --check-web

정상 출력: 웹 인증·명령 조회 정상 (보드 연결·명령 전송 없음)
401/403이면 새 토큰과 계정 권한을 확인합니다.

직렬 장치 없이 명령 수신을 시험하려면:
.\.venv-bridge\Scripts\python.exe signal_bridge.py --dry-run

실제 연결은 정상 보드·배선·펌웨어 확인 후 진행합니다.
.\.venv-bridge\Scripts\python.exe signal_bridge.py --port COM4 --baud 9600

- 현재 전달받은 signal_bridge.py 프로토콜 기본 속도는 9600입니다.
- 시작 시 정지 명령을 보내고 이전 웹 명령은 건너뛰며 새 명령을 기다립니다.
- 종료: Ctrl+C. 코드가 정지 명령을 전송하도록 구현되어 있습니다.
- 최초 확인은 정지 상태 통신부터 진행합니다. 실제 정지 수신은 현장 확인이 필요합니다.

7. 혼동하면 안 되는 두 종류의 제어
A. 현재 signal_bridge.py
- 운영 웹 /api/test-control을 읽고 HC-06 직렬 명령으로 전달합니다.
- DISPATCH: M,20,0 / ESTOP: S / 구조망: F,각도
- 출동 중 0.5초 간격으로 주행 명령을 재전송합니다.
- RETURN은 현재 정지일 뿐, 실제 복귀 항법이 아닙니다.
- CLEAR_ESTOP은 M,0,0을 보내며 펌웨어의 정지 래치가 해제되는지는 미검증입니다.
- 이 브릿지는 ArUco 좌표 기반 PID 조향을 수행하지 않습니다.

B. backend/app/routers/boat.py의 LAN PID 제어
- /api/boat/pose → /api/boat/command 경로의 별도 로컬 제어기입니다.
- Kp=0.8, Ki=0, Kd=0.15 기본값, 조향 제한·적분 누적 방지가 구현돼 있습니다.
- BOAT_BRIDGE.md의 예전 $D/$N/$S·38400bps 브릿지 설명은 A와 다른 프로토콜입니다.
- bridge.py는 현재 웹 저장소에 포함되어 있지 않습니다. 있다고 가정하고 실행하지 마세요.
- 하드웨어 담당자의 실제 펌웨어·브릿지와 프로토콜을 맞추기 전까지 A와 B를 섞지 않습니다.
- PID 실물 연결과 자동 출동 연결은 아직 남은 개발·검증 항목입니다.

8. 카메라·AI·현장 보정 순서
1) 운영 웹 로그인 → 사이트 선택 → 관제 화면 '카메라 연결' → 권한 허용
   브라우저 카메라가 Modal AI에 자동 연결됩니다. 별도 로컬 AI 버튼은 필요 없습니다.
2) 카메라를 고정하고 설정 화면에서 실제 영상을 보며 ROI를 조정·저장
3) 호모그래피: 좌상 → 우상 → 우하 → 좌하의 기준점 4개 지정
   현재 구현은 첫 4개를 보정 영역 모서리로 사용합니다. 추가 기준점 개수 제한은 없습니다.
4) 실제 너비·세로 길이(m)를 입력하고, 추가점이 있으면 실제 X·Y도 입력
5) '저장 전 보정 확인' → 오류 확인 → '호모그래피 저장 · 적용'
6) '별도 실측 지점으로 정확도 확인'에서 피팅에 쓰지 않은 지점을 선택
   실측 X·Y를 입력해 실제 오차를 확인합니다. 이 확인은 설정을 저장하지 않습니다.
7) ArUco: 실제 사전·ID·마커 한 변 길이 설정 → 저장·적용
   길이는 흰 여백을 제외한 마커 자체의 길이이며 보드 길이가 아닙니다.
8) 실제 보드 앞쪽 방향 기준 보정 각도를 측정한 뒤 '보드 방향 보정 완료' 체크
   측정 전 임의의 0도를 측정값으로 저장하지 않습니다.
9) '저장한 설정으로 현재 영상 확인'에서 검출·좌표·앞뒤 화살표 확인

좌표: 실제 영역 좌하단 원점, +X 오른쪽, +Y 위쪽, 단위 m.
영상 픽셀 좌표의 Y는 아래로 증가하므로 실제 좌표 Y와 구분해야 합니다.
카메라 위치·각도·영상 비율이 바뀌면 재보정합니다.
기본 ROI는 짧은 화면 변의 88% 크기인 4점 정사각형입니다.
저장한 ROI가 있으면 저장값이 우선하며, 설정에서 초기화하면 기본값으로 돌아갑니다.

9. 남은 검증 항목
[ ] 실측 기반 호모그래피 저장 및 별도 지점의 오차 확인
[ ] ArUco 이동·회전·가림 시 위치·앞뒤 방향 확인
[ ] 실제 영상에서 동일 대상의 익수 점수 0.8 이상, 15프레임 연속 판정 확인
[ ] 이동·가림·교차 상황의 추적 ID 유지 확인
[ ] 장시간 연결·재접속·네트워크 지연·초기 추론 지연 확인
[ ] 웹 → 브릿지 → 보드의 통신·정지·비상정지 실물 확인
[ ] 실제 좌표를 사용하는 PID 조향 연결과 저속 튜닝
[ ] 판정 성립 후 3초 내 출동 명령, 실제 출동·복귀·완료 검증

15프레임을 3초 안에 모으는 조건은 아닙니다.
이미 통과한 합성 응답/ByteTrack 자동 시험은 실제 모델 정확도나 실물 출동을 입증하지 않습니다.
초기 추론이 약 32초 걸려 결과가 만료된 사례가 있습니다.
새 프레임 재시도는 정상 수신됐지만 초기 지연 자체가 완전히 제거된 것은 아닙니다.

10. 데스크톱에서 코드도 수정하려는 경우
주요 파일:
code/dashboard.html — 관제·카메라·설정 화면
code/js/camera.js — 브라우저 카메라 → AI 분석
code/js/vision-settings.js — 호모그래피·ArUco·검증점 UI
code/js/dashboard.js — ROI·기본 관제 동작
backend/platform/routers/camera_settings.py — 설정 저장·검증 API
backend/platform/camera_configuration.py — 보정값 검증·호모그래피 계산
backend/app/routers/boat.py — LAN PID 제어기
signal_bridge.py — HC-06 웹 신호 브릿지
Ai파일/services/tracking/ — CPU 추적 서비스·통합 시험
Ai파일/edge-vision/ — 전달받은 독립 보정·ArUco 측정 도구
MODEL_STREAM.md / BOAT_BRIDGE.md / EDGE_INTEGRATION.md — 상세 기록

웹 백엔드를 로컬 개발할 때만 별도 환경을 만듭니다.
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt

로컬 로그인용 DG_ADMIN_ID, DG_ADMIN_PW, DG_SECRET_KEY를 별도 환경변수로 설정합니다.
로컬 웹의 AI 연결에는 VISION_SERVICE_URL, VISION_SERVICE_API_KEY도 필요합니다.
키는 기존 비공개 설정에서 안전하게 전달받고 Git에 올리지 않습니다.
이 변수들을 .env 파일에 적기만 하면 모든 실행기가 자동으로 읽는다고 가정하지 마세요.
환경변수로 주입한 뒤 다음을 실행합니다.

.\.venv\Scripts\python.exe -m uvicorn backend.app.main:app --host 127.0.0.1 --port 8000

브라우저: http://127.0.0.1:8000
HTML 파일을 더블클릭하거나 file:// 주소로 열지 않습니다.
로컬 DB는 기본 SQLite이며 운영 웹의 계정·설정과 별개입니다.
운영 DB 접속값을 로컬 테스트용으로 무심코 복사하지 않습니다.

11. Mac에서 그대로 복사하면 안 되는 것 / 별도 전달할 것
- Mac의 .venv*는 Windows에서 실행할 수 없습니다. 위 명령으로 새로 만듭니다.
- .env.local, .env.edge-handoff, Vercel·Modal 로그인 설정과 API 키는 Git에 없습니다.
- Ai파일/local-model 및 모델 가중치·원본 ZIP 등은 Git에서 제외된 로컬 자산입니다.
- 운영 웹으로 카메라 분석만 할 때는 모델 파일·Moondream 키가 데스크톱에 필요 없습니다.
- AI를 오프라인으로 실행하거나 Modal을 다시 빌드하려면 별도 모델·소스·환경을 전달받아야 합니다.
- Ai파일/services/tracking의 통합 시험도 기존 CPU 빌드 컨텍스트가 필요합니다.
- Mac의 자동 Git 동기화 스크립트는 데스크톱에 자동 설치되지 않습니다.
- 코드 변경 후 git status → 변경 파일을 지정해 git add → git commit → git push 순서로 진행합니다.
- Vercel 배포 READY와 실제 운영 반영을 확인한 뒤 완료로 판단합니다.

12. 다음 개발자에게 전달할 요약
현재 운영 웹은 브라우저 카메라 → Vercel → Modal AI 구조입니다.
카메라 연결만으로 분석이 시작되고, ROI·호모그래피·ArUco 설정과 저장 전 검증,
별도 실측점 오차 확인 기능이 있습니다. 정사각형 기본 ROI도 반영되어 있습니다.
자동 시험은 있으나 현장 보정·실제 영상 정확도·장시간 안정성·실물 보드 제어는 남아 있습니다.
HC-06 signal_bridge.py와 LAN PID 제어는 별개이며, 신호 브릿지만 켜서 자동 복귀까지 되는 구조는 아닙니다.
다음 순서: 웹 인증 조회 → 정상 모듈 페어링/포트 확인 → 정지 상태 통신 확인 →
카메라 실측 보정 → 실제 AI 판정 검증 → 좌표 기반 보드 조향 연결 → 실물 전체 흐름 검증.
