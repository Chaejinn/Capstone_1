카메라·AI 모델 연결 관련 대화 기록
날짜: 2026-10-24

기록 범위: 현재 대화에서 확인할 수 있는 사용자 요청과 최종 답변 본문.
IDE 자동 첨부 정보, 작업 중 진행 메시지, 도구 내부 호출·로그는 제외했습니다.
이미지는 설명으로 표시했습니다. API 키 값은 마스킹했습니다.
아래 답변에는 당시의 잘못된 안내도 포함됩니다. 검증된 사실만 모은 문서가 아니라 대화 기록입니다.
최종 상태: 사용자는 계속 3개 카메라 선택 메뉴가 보인다고 보고했습니다. 해당 화면 불일치 문제는 해결이 확인되지 않았습니다.

────────────────────────────────────────
1. 사용자
카메라랑 연결 어디까지 진행되었는지?

답변
현재 카메라 영상을 관제 화면에 띄우는 코드는 구현됐고, 실제 장비와 연결한 최종 확인은 남아 있는 상태입니다.

- 이 기기 카메라: 브라우저 권한을 허용하면 실시간 미리보기를 표시합니다. AI 분석은 적용되지 않습니다.
- 기존 웹캠 서버: 로그인 인증 후 MJPEG 영상을 받아 표시하도록 구현돼 있습니다.
- AI 분석 영상: RF-DETR → ByteTrack → Moondream의 분석 결과가 그려진 영상을 받아오는 서버와 화면 연결 코드가 있습니다. 실제 사용하려면 모델 PC 실행, 연결 키, HTTPS 영상 서버 주소가 필요합니다.
- 판정·구조보드 제어: 영상 연결만으로 자동 실행되지는 않습니다. 별도 연동 확인이 필요합니다.

방금 영상 서버 테스트 3개는 통과했습니다. 프런트 테스트는 현재 환경에 Node가 없어 실행하지 못했고, 실제 카메라 영상 수신 여부는 아직 확인하지 않았습니다.

접속 위치는 관리자 로그인 화면이 아니라 관제 대시보드 → ‘실시간 카메라 연결’입니다. 연결 방법은 MODEL_STREAM.md에 정리돼 있습니다.

────────────────────────────────────────
2. 사용자
저 카메라 모델코드가 배포가 제대로 되었는지도 확인가능해?

답변
네. 방금 실제 서버에 접속해서 확인했습니다.

- 웹사이트 서버: 정상 응답입니다. 다만 카메라와 실시간 기능은 비활성화돼 있습니다 (camera_enabled: false, realtime_enabled: false).
- 코드에 예시로 적힌 Modal AI 서버: 정상 응답이며, GPU 사용과 모델 로딩 완료가 확인됩니다 (device: cuda, model_loaded: true).
  https://kbkr504--drown-guardian-api-fastapi-app.us-east.modal.run/health

즉, AI 서버는 살아 있고 모델도 로딩돼 있습니다. 다만 상태 응답만으로 실제 이미지 분석 성공이나 카메라 → AI → 관제 화면 연결까지 확인된 것은 아닙니다.

카메라 영상 서버는 별도로 실행하는 구조인데, 저장소에는 실제 배포 주소가 없습니다. 대시보드에 입력한 ‘영상 서버 주소’를 알려주시면 해당 서버도 확인하겠습니다. 연결 키는 채팅에 보내지 마세요.

김규량 담당자가 보낸 거야 이걸 토대로 확인해줘

답변
담당자가 보내준 주소로 직접 확인했습니다.

GET /health: 200 정상 — CUDA 사용, 모델 로딩 완료
POST /detect: 401 인증 필요 — Bearer API key required
GET /stream: 404 없음 — 현재 영상 스트림 경로 미제공

AI 추론 API는 배포돼 응답하고 있습니다. 다만 인증 키가 없어 실제 이미지를 넣었을 때 추론 결과가 정상인지까지는 확인하지 못했습니다.

또한 현재 대시보드의 ‘AI 분석 영상’은 /stream을 요구하므로, 보내주신 서버 주소만 입력해서는 연결되지 않습니다. 카메라 프레임을 /detect에 전송하고 결과를 화면에 표시하는 연동이 필요합니다.

다음 확인에 필요한 것은 담당자의 API 키와 /detect 요청 예시입니다. 키는 채팅이나 코드에 넣지 말고 로컬 환경변수 DG_AI_KEY로 설정해 주시면 실제 추론까지 점검할 수 있습니다.

- 요청: POST /detect, 인증 헤더 + multipart/form-data
- 테스트: 사람이 없는 640×480 PNG 이미지, frame_id=1

따라서 인증·이미지 업로드·탐지 모델 실행은 현재 정상 동작합니다. 다만 사람이 없는 이미지라 Moondream 분류는 실행되지 않았습니다 (classification_ms: 0). 담당자가 말한 오류가 사람 탐지 후 분류 단계에서 발생하는지는 추가 확인이 필요합니다.

또한 현재 백엔드는 탐지 결과가 비어 있으면 판정 변환에서 422 오류를 반환하는 코드가 있습니다. 서버의 정상 응답도 연동 과정에서 오류로 보일 수 있습니다.

오류가 났던 이미지와 응답 내용이 있으면 같은 조건으로 원인을 좁힐 수 있습니다. 공유된 두 API 키는 점검 후 재발급하는 것이 좋습니다.

VLM·탐지 모델과 가중치: 이 프로젝트 폴더에 없음
Modal AI API 호출 코드: 있음 — ai_client.py
별도 모델 저장소 실행용 스크립트: 있음 — scripts/model_stream.py
브라우저 카메라 미리보기: 구현됨
카메라 → Modal 자동 분석 → 화면 표시: 아직 연결되지 않음

모델을 이 폴더에 설치하지 않아도 Modal 서버를 이용해 분석할 수 있습니다. 앞서 사진으로 탐지와 분류가 성공한 것도 이 방식입니다.

다만 주소와 키만 입력하면 지금 화면에서 바로 작동하는 상태는 아닙니다. 다음 작업이 필요합니다.

1. 백엔드에 Modal 주소와 API 키 설정
2. 카메라 프레임을 캡처해 /detect로 전송
3. 응답의 bbox, water_state를 화면에 표시하도록 연결
4. 현재 판정 변환 코드 수정 — 실제 응답의 water_state 대신 class를 읽고 있어 잘못 해석할 수 있음

즉, 모델 서버는 준비돼 있고, 이 웹사이트와 이어주는 작업이 남아 있습니다.

17. 사용자
저번엔 로컬로 돌렸을 떄 내 얼굴에 체킹박스가 떴는데 그건 어떻게 된거임?

답변

제가 확인한 현재 로컬 코드의 ‘이 기기 카메라’는 영상만 표시하며, 얼굴을 탐지해 박스를 그리는 기능은 없습니다. 따라서 예전에 실행했던 코드·서버가 지금과 달랐거나, 별도 모델 서버가 그린 영상을 보고 있었을 수 있습니다.
