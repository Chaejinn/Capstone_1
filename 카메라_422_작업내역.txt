카메라 연결 422 오류 점검 및 개선 작업 내역
작성일: 2026-11-05 (한국 시간)

1. 오류 발생 경로 확인
- 처음에는 로그인 관련 오류로 살펴봤으나, 사용자 설명에 따라 카메라 연결 경로를 점검했다.
- code/js/auth.js는 공통 API 요청 및 오류 표시 코드다. 이 파일의 fetch 위치에 오류가 표시되더라도 원인은 해당 API의 서버 응답일 수 있다.
- 카메라 화면은 브라우저 카메라의 프레임을 /api/vision/streams 경로로 업로드하고, 서버가 추적 서비스로 전달한다.

2. 기존 422 원인 확인
- 저장소의 MODEL_STREAM.md에 기록된 실패 사례는 프레임 촬영 시각 검증 실패였다.
- 프레임 접수 제한은 촬영 후 2초이며, 기록된 실패 요청의 도착 시 나이는 2.768초였다.
- 해당 기록에서 인증·사이트 DB 조회는 1,982.4ms, 추적 서버 왕복은 240.4ms였다.
- 이는 기존 기록에 근거한 원인으로, 사용자가 처음 본 오류 응답 자체를 직접 확보한 것은 아니다.

3. DB 연결 풀 반영 확인
- 로컬 backend/platform/database.py에서 연결 풀 개선을 확인했다.
- Vercel 운영 배포의 실제 소스도 조회해 같은 개선이 반영돼 있음을 확인했다.
- 주요 설정: pool_size=2, max_overflow=1, pool_timeout=10초, pool_recycle=240초, pool_pre_ping=True.
- 사용자 활성 여부와 사이트 권한은 매 요청 DB에서 확인하는 구조를 유지했다.
- 이번 작업에서 DB 풀 코드를 추가 변경하지는 않았다.

4. Vercel 인증 복구
- 처음 운영 조회 시 HTTP 403이 발생했다.
- 재조회 결과 invalidToken 응답을 확인해 저장된 액세스 토큰이 유효하지 않음을 확인했다.
- Vercel 공식 CLI의 갱신 방식을 확인하고 기존 리프레시 토큰으로 인증을 갱신했다.
- 갱신된 인증을 로컬 Vercel 인증 파일에 저장했다. 인증키와 DB 비밀번호는 이 문서에 포함하지 않았다.

5. 운영 리전 확인 및 변경
- 변경 전 실제 운영 함수 리전: 미국 동부 iad1.
- 운영 DB: Neon, AWS 싱가포르 ap-southeast-1.
- 로컬 vercel.json은 서울 icn1이었지만 실제 운영 배포는 iad1이었다.
- Vercel 프로젝트의 Fluid 함수 기본 리전을 싱가포르 sin1로 변경했다.
- 로컬 vercel.json의 regions도 sin1로 변경했다.
- 기존 운영 소스를 싱가포르 리전으로 재배포했다.
- DB 자체를 이전하거나 프레임 접수 제한 2초를 변경하지는 않았다.

9. 로컬 테스트 제약
- .venv에서 진단 테스트를 실행했으나 Python 버전의 타입 문법 호환 문제로 수집 단계에서 실패했다.
- backend/.venv에서 다시 실행했으나 bcrypt 모듈 부재로 가져오기에 실패했다.
- 따라서 로컬 진단 단위 테스트가 통과했다고 판단하지 않았다. 위 운영 API 검증 결과는 별도로 확인한 사실이다.
